# superfluid 0.1.7

**0.1.6's packages for npm and Homebrew.** 0.1.6 reached GitHub and crates.io
but not npm or the Homebrew tap: the install test that gates those uploads
still expected 0.1.5's `superfluid self update` wording and failed on 0.1.6's.
This release is 0.1.6 with that test corrected; nothing else changes. See
[0.1.6's note](https://github.com/basecompute/superfluid/releases/tag/v0.1.6)
for what it carries: a fleet link that stays up while a node generates,
`self update` through the package manager, Gemma 4's embedded MTP head, the
`<id>@<install>` forms, the `runtimes` columns, decode timed per tick and
llama.cpp b11981.

## Fixed

- The packaging test (`packaging/try-install.sh`, run before any upload)
  takes `self update --dry-run`'s 0.1.6 wording: the package manager named,
  its command either shown (where superfluid would run it) or named (where it
  leaves it to you), and the copy unchanged.

See [installation](https://github.com/basecompute/superfluid/blob/v0.1.7/docs/getting_started/installation.md)
for every way to install superfluid, and
[updating](https://github.com/basecompute/superfluid/blob/v0.1.7/docs/serving/updating.md)
for how each is updated.
