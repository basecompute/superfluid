# superfluid 0.1.10

**`--speculate auto` drafts with the faster drafter.** On the basert runtime,
`auto` now drafts Qwen3.8-27B and Qwen3.6-35B-A3B with their DFlash2
drafters, pulled the first time, where it took the model's own MTP head. On an
M5 Pro, Qwen3.8-27B at Q4 decodes in 21.3 / 11.1 / 18.3 ms a token (coding /
math / Q&A prompts) where the head took 27.1 / 22.0 / 24.7 and plain decoding
53.2. Tool calls stream as they are generated, XML ones (Qwen3.5, 3.6 and
3.8) included, and a model pulled by id shows its progress.

## New

- **`auto` takes the drafter the hub catalog pairs with the model.** BaseRT's
  hub catalog marks a drafter for some targets, and `--speculate auto` takes
  that drafter ahead of the bundle's own head: today
  `basecompute/Qwen3.8-27B-DFlash2` for Qwen3.8-27B and
  `basecompute/Qwen3.6-35B-A3B-DFlash2` for Qwen3.6-35B-A3B. When no copy is
  installed, its `default-q4` file is pulled with the basert runtime before
  the model is sized, for every model served: the first, the others given
  with `--model`, and the ones loaded later through `--model-dir` or
  `/v1/models/load`. Nothing is pulled with `--offline`; a pull that fails is
  said, and `auto` settles among what is installed. The model's own head and
  the other fitting drafters stay the fallbacks, so a drafter the engine
  refuses gives way to them instead of stopping the start. macOS only, where
  the pairings were measured; Gemma 4 keeps its embedded head. The pairings
  arrive with the catalog BaseRT 0.4.6 publishes.
  See [How `auto` picks a drafter](https://github.com/basecompute/superfluid/blob/v0.1.10/docs/features/speculative_decoding.md#how-auto-picks-a-drafter).
- **A pull shows its progress.** A model pulled by id
  (`superfluid serve org/model`) shows a progress bar on stderr with the
  percentage, the bytes of the total, the rate and the time left, the same
  for the llama.cpp, MLX and basert runtimes, and leaves one line with the
  download's size, time and rate. Where stderr is not a terminal it prints a
  line every ten seconds instead. Before, only llama.cpp drew a bar, and
  only on a terminal.
  See [Pulling models by id](https://github.com/basecompute/superfluid/blob/v0.1.10/docs/models/supported_models.md#pulling-models-by-id).

## Changed

- **Tool calls stream at token cadence.** A streamed tool call's arguments
  now arrive token by token, as text does. On the basert runtime a call
  shorter than one engine tick (at least 32 tokens) used to arrive whole.
  See [Streaming](https://github.com/basecompute/superfluid/blob/v0.1.10/docs/features/tool_calling.md#streaming).

## Fixed

- **XML tool calls stream, under their own name.** Qwen3.5, 3.6 and 3.8 call
  tools in XML (`<function=write><parameter=path>…`). Streamed, such a call
  reached the client whole once it closed, on every runtime, and one whose
  argument held a JSON object (writing a `package.json`) was streamed under
  that object's `"name"` field instead of the tool's, so a client that keeps
  the first name it sees could not run it. The name now goes out as soon as
  it is known and the arguments one at a time. Two calls in a row, or text
  right after a call, no longer interleave in the stream. Non-streaming
  responses were not affected.
- **A node joining a fleet** could be marked as gone for a moment right
  after it joined, when the head reached it before its connection was in
  place.
