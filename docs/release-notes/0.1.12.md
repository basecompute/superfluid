# superfluid 0.1.12

**superfluid installs BaseRT on AMD GPUs.** On Linux x86-64 with an AMD
Ryzen AI Max (Strix Halo: Radeon 8060S or 8050S), or a Ryzen AI 300 or 400
with a Radeon 890M or 880M (Strix Point, Gorgon Point), and ROCm 10,
`superfluid runtime install basert` and the install script now install the
ROCm engine BaseRT 0.5.0 publishes, where they refused any x86-64 machine.
llama.cpp b12317 is the build `superfluid runtime install llamacpp`
installs, and the `serve` monitor's log pane scrolls properly.

## New

- **The BaseRT runtime on AMD GPUs.** On Linux x86-64, superfluid reads the
  GPUs the AMD kernel driver reports and, for a gfx1151 (Strix Halo) or
  gfx1150 (Strix Point, Gorgon Point) GPU, installs BaseRT's ROCm engine,
  one bundle for both. It needs ROCm 10 under `/opt/rocm/core-10.0`, and
  says what to install when that is missing; see BaseRT's
  [installation](https://github.com/basecompute/baseRT#1-install) for the
  Linux and ROCm versions it runs on. The install script does this on its
  own when the machine has an AMD GPU driver, and carries on without the
  engine when the GPU is not one BaseRT runs on (a Radeon 860M or 840M, for
  example), as it does on arm64. The engine runs on the first GPU HIP
  lists: on a machine with another AMD GPU ahead of the Strix one,
  superfluid says which `HIP_VISIBLE_DEVICES=<n>` selects it.
  `superfluid devices` names the engine `ROCm` and the GPU by its target.
  See [runtimes](https://github.com/basecompute/superfluid/blob/v0.1.12/docs/models/runtimes.md).

## Changed

- **llama.cpp b12317** is the build `superfluid runtime install llamacpp`
  installs; b12283 is a tested build too, and b12244, b12219, b12207,
  b12125, b12102, b12068, b11981, b11951, b11925, b11890, b11889, b11642 and
  b11284 stay.

## Fixed

- **Ollama management requests get their answer.** `ollama pull`, `push`,
  `create`, `copy` and `delete` against superfluid, which does not manage
  models through those routes, could see the connection reset instead of
  the 501 that says so, when the client sent the request's body after its
  head. superfluid now reads the body before it answers.
- **The `serve` monitor's log pane.** Scrolling down did nothing for a while
  after scrolling up past the top, a long line could hide the newest lines
  while following the log, and a scrolled-up view moved as new lines
  arrived. The pane now scrolls by screen rows and holds still while you
  read; PgUp and PgDn move a page, `Home` and `End` (or `g` and `G`) jump to
  either end, and a progress bar's carriage returns or a worker's colour
  codes no longer tear the display.

The engine ABI is unchanged: superfluid 0.1.12 serves BaseRT 0.5.0 and the
0.4 releases on Apple silicon and NVIDIA as 0.1.11 does.

See [installation](https://github.com/basecompute/superfluid/blob/v0.1.12/docs/getting_started/installation.md)
for every way to install superfluid, and
[updating](https://github.com/basecompute/superfluid/blob/v0.1.12/docs/serving/updating.md)
for how each is updated.
