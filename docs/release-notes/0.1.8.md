# superfluid 0.1.8

**A drafter named by its hub id.** `superfluid serve --speculate dflash:org/drafter`
now pulls the drafter the way a model given by id is pulled, with the target's
runtime, before anything loads. Before, the id was read as a file path and the
server failed after loading the target. And for Homebrew 6 and later, which
load a third-party tap only once it is trusted: `brew trust basecompute/tap`
before `brew install basecompute/tap/superfluid`.

## Fixed

- `superfluid serve --speculate <strategy>:<id>` with `dflash`, `dspark`,
  `eagle3` or `draft-model` read the id as a file path: the target loaded, then
  registering the strategy failed with "draft-model weights are not readable by
  the daemon". Only `basert serve`, which rewrites a drafter id to its installed
  path, took the id form. The drafter is now pulled with the target's runtime
  as a model given by id is, right after the runtime's options settle, so
  resolution, the catalog check, context sizing and the engine all see the real
  path. An installed drafter is found without a download, `:<variant>` goes
  with the id (`eagle3:org/head:default-q4`), and `--offline` with nothing
  installed, or a failed pull, exits 1 before the target loads. Paths, `auto`,
  `mtp-head` and `prompt-lookup` are unchanged.
- The packaging install test that gates the npm and Homebrew uploads stopped
  on macOS before any upload, because Homebrew now refuses a formula from an
  untrusted tap; it trusts its throwaway tap for the run. 0.1.7's npm packages
  and Homebrew formula were published by hand; this release's come from the
  workflow again.

## Changed

- Installing with Homebrew on Homebrew 6 or later takes one more step,
  `brew trust basecompute/tap`, before `brew install basecompute/tap/superfluid`
  (`brew trust --formula basecompute/tap/superfluid` trusts the one formula).
  An older Homebrew has no `trust` command and needs none. A copy installed
  before this is already trusted, and `brew upgrade superfluid` works as it did.

See [installation](https://github.com/basecompute/superfluid/blob/v0.1.8/docs/getting_started/installation.md)
for every way to install superfluid, and
[updating](https://github.com/basecompute/superfluid/blob/v0.1.8/docs/serving/updating.md)
for how each is updated.
