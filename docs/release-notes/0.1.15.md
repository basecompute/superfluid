# superfluid 0.1.15

**A fleet serves the models its machines bring, without a restart.** A
fleet head now serves a model that a joining node brings, a node started
without `--model` follows its head's model, nodes join only their own
fleet's head when two fleets share a network, and `superfluid fleet nodes`
and `superfluid fleet remove` list and remove nodes. `superfluid serve
--presence-penalty` gives BaseRT models a default presence penalty, and a
model already downloaded starts without waiting for its Neural Engine
compile.

## New

- **A head serves the models its nodes bring.** When a node joins a fleet
  head with a model the head does not serve, the head starts serving it,
  with that node's tokenizer and chat template: it appears in `/v1/models`
  and answers requests, with no restart. `/v1/models/load` on a head
  serves a model that a running node serves, and `/v1/models/unload` drops
  one until it is loaded again, even when nodes serving it rejoin. A model
  stays listed after its last node leaves, and requests for it get a 503
  until a node returns. See
  [distributed serving](https://github.com/basecompute/superfluid/blob/v0.1.15/docs/serving/distributed_serving.md).
- **Nodes that follow their head.** `superfluid node join` no longer needs
  `--model`. Without it, the node finds its fleet's head on the local
  network, downloads the model the head serves and serves it. When the
  head moves to another machine or changes its model, the node finishes
  what it is running (for up to 30 seconds) and starts again with the new
  model. A node given `--model` keeps that model, as before.
- **List and remove a fleet's nodes.** `superfluid fleet nodes` lists a
  head's nodes with each one's models, sessions and load, and `superfluid
  fleet remove <name>` takes a node out until the head restarts: what ran
  there moves to another node, and the removed node exits with code 5.
  Over HTTP they are `GET /v1/fleet/nodes` and `DELETE
  /v1/fleet/nodes/{name}`. Removing a node needs an admin key, or, on a
  head with no key, a request from the head's own machine.
- **A default presence penalty.** `superfluid serve --presence-penalty
  <value>`, from -2 to 2, gives every request that sends no presence
  penalty this one, on BaseRT models. A request's own value still wins,
  and `"presence_penalty": 0` opts out. `/props` reports the default. On
  llama.cpp and MLX the default is not applied, because it would take
  every request off the runtime's own sampler, and the start says so. See
  [sampling](https://github.com/basecompute/superfluid/blob/v0.1.15/docs/features/sampling.md).
- **`superfluid models`** lists the models downloaded here, with their
  runtime, size and path; with `--catalog` it lists the catalog's models
  too, marking those that are here. `--json` prints both lists for
  programs.
- **JSON for programs that run superfluid.** `superfluid serve --log-format
  json` and `superfluid node join --log-format json` write every line on
  stderr as a JSON object: the start-up steps, download progress, model
  loads, a `serve.ready` event with the address the server bound, fleet
  events, and an `error` event with the exit code when a start fails.
  `superfluid launch --json` lists the agents `launch` knows and the server
  it started. See
  [events](https://github.com/basecompute/superfluid/blob/v0.1.15/docs/serving/events.md).
- **The API key from a file.** `superfluid serve --api-key-file <path>`
  reads the key from a file, so it no longer shows in `ps`, and warns when
  other users can read the file. `superfluid launch` now hands the key to
  the server it starts in the environment instead of the arguments, and
  `superfluid top` takes `--api-key-file` too.

## Changed

- **`SUPERFLUID_API_KEY` turns authentication on for `superfluid serve`.**
  With no `--api-key` or `--api-key-file`, `serve` now reads the key from
  `SUPERFLUID_API_KEY`, the variable `superfluid launch` already read, and
  says so when it starts. A shell that sets it for `launch` now also
  protects a `serve` started from it. See
  [security](https://github.com/basecompute/superfluid/blob/v0.1.15/docs/deployment/security.md).
- **A node joins only its own fleet.** A fleet head with a token now
  announces which fleet it belongs to, so when two fleets share a local
  network, a node joins only its own fleet's head and says once that
  another fleet's head answered. A head from an earlier release, which
  announces no fleet, is still joined when no head of the node's own fleet
  answers.
- **Fleet metrics name each node's models.** Every
  `superfluid_fleet_node_*` series on a head's `/metrics` has a `model`
  label, and `superfluid_fleet_head_info` lists every model the head serves
  in `models`. A node's series start over when it first reports its
  models, so a dashboard that matches `{node, addr}` exactly needs `model`
  added or ignored. `superfluid top` shows each node's model.
- **llama.cpp b12470** is the build `superfluid runtime install llamacpp`
  installs; b12435 is a tested build too, and b12408, b12359, b12317,
  b12283, b12244, b12219, b12207, b12125, b12102, b12068, b11981, b11951,
  b11925, b11890, b11889, b11642 and b11284 stay.

## Fixed

- **A model already downloaded starts without waiting for its Neural
  Engine compile.** Since 0.1.11, `superfluid serve` on a Mac waited for
  the Neural Engine to compile a model's programs whenever macOS had none
  for it, which happens after every superfluid, BaseRT or macOS update:
  Qwen3.8-27B took about 48 seconds to be ready on an M5 Max, instead of 7
  to 14. A model already on disk now starts at once and compiles in the
  background while the GPU prefills alone; on that Mac it was ready in 16.6
  seconds. A model just downloaded still compiles before it starts.
- **`/props` for a model not loaded yet.** On a server with several
  models, `/props?model=<m>` for one not loaded yet could advertise the
  default model's speculative-decoding temperature cap, so a client that
  echoed it ran at a different temperature than one that left it out. The
  temperature is now left out until the model loads, where its speculative
  decoding could change it.

The engine ABI is unchanged: superfluid 0.1.15 serves BaseRT 0.5.2,
released alongside, and the 0.5 and 0.4 releases as 0.1.14 does. BaseRT
0.5.2 states in its capability record that it applies sampling penalties
itself, and superfluid assumes so for older BaseRT releases; a BaseRT
installation made by superfluid 0.1.14 or older takes `--presence-penalty`
once it runs BaseRT 0.5.2, or after `superfluid runtime repair`. BaseRT
0.5.2 also brings Qwen3.6-35B-A3B and gemma-4-26B-A4B as BaseQuant models:
`superfluid serve basecompute/Qwen3.6-35B-A3B-BaseQuant-V1 --runtime basert`
serves its Medium file.

for every way to install superfluid, and
[updating](https://github.com/basecompute/superfluid/blob/v0.1.15/docs/serving/updating.md)
for how each is updated.
