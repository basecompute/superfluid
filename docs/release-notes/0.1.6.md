# superfluid 0.1.6

**A fleet link stays up while a node generates, and `self update` runs the
package manager.** A generation longer than a node's idle timeout or its lease
no longer drops the link or hangs the request, and a node that goes silent is
given up after 30 s. `superfluid self update` on a copy Homebrew, npm, pipx, uv
or cargo installed runs that manager's update, after asking.

## New

- **Gemma 4's MTP head, inside the bundle.** A baseRT bundle that carries
  Google's Gemma 4 head (`basert add-speculator`, and the `basecompute`
  Gemma 4 E2B and E4B bundles from BaseRT 0.4.3 on) is an MTP head to
  `--speculate mtp-head` and to `auto`, like a Qwen3.5 bundle's own head:
  `superfluid serve basecompute/gemma-4-E4B-it --speculate mtp-head`. The
  engine drafts over the target's KV; on an M5 Pro the E4B Q8 bundle decodes
  1.6 times faster at one request. The refusal for a bundle without a head
  names `basert add-speculator`.
- `superfluid runtime remove`, `repair` and `use` take an install as
  `superfluid runtimes` lists it, `<id>@<install>` (`basert@0.3.0-metal`).
  `remove <id>` with more than one install needs `--all`, so a copied row
  never removes more than it names.

## Changed

- `superfluid self update` on a copy a package manager installed runs that
  manager's update (`brew upgrade`, `npm install --global`, `pipx upgrade`,
  `uv tool upgrade`, `cargo install`) after asking; `--yes` skips the
  question and is required without a terminal, `--dry-run` shows the command,
  and `--version` is refused because the manager chooses versions. It only
  names the command for a pinned formula, another user's Homebrew, an npm
  folder that needs root, a project's npm dependency, or pip in an
  environment, and runs nothing while a server runs from the copy. The
  superfluid that `basert serve` installs beside basert is left to
  `basert self update`.
- A request's decode rate is timed per tick: the tokens after a request's
  first tick, over the time from that tick's end to the last tick's end,
  stamped once per tick as the engine returns rather than once per delivered
  event. The access log's `decode=` is now right when a tick hands a lane
  several tokens at once (reasoning tags, channel changes), where it was
  missing or inflated, and the decode-cost estimate counts decode rounds only.
- `superfluid runtimes`: INSTALLABLE agrees with `runtime install` (an installed
  release newer than the listed versions that `install` would choose shows as
  `(installed)`), DEVICE is the memory budget the runtime serves within, and
  WORKER is short; `--json` keeps the full paths and figures.
- llama.cpp b11981 is the build `superfluid runtime install llamacpp`
  installs; b11951 and b11925 are tested beside it, and b11890, b11889, b11642
  and b11284 stay.

## Fixed

- A fleet node's link did no liveness work while it generated: a generation
  longer than the idle timeout (120 s) was dropped as soon as it finished, one
  longer than its lease (60 s) hung the request, and a node that went quiet
  without closing its socket hung the head's request for good. An end now
  sends a keepalive after 5 s of silence and gives the link up after 30 s,
  a generation runs on its own thread while the link keeps reading cancels,
  lease grants and heartbeats, and the head bounds its wait. A node or head on
  the previous link version still works, without the silence timeout.
- `superfluid runtime remove basert@0.3.0-metal`, the form `runtimes` prints,
  was refused as not a runtime id.
- `superfluid runtimes` offered an older release as installable than
  `runtime install` would pick, and said an installed newer one needed
  `--untested`.
