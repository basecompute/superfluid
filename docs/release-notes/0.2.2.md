# superfluid 0.2.2

**superfluid now keeps itself and its runtimes up to date.** From this release on, superfluid checks once a day for a newer release. When it finds one, it updates before the next `serve`, `launch`, `node`, `top` or `runtime` command you start in a terminal, brings the runtimes you installed forward with it, and then runs your command on the new version. `superfluid self auto-update off` turns this off. llama.cpp b12776 is now the build `superfluid runtime install llamacpp` installs on macOS, Linux and Windows.

## New

- **Automatic updates.** Once a day superfluid checks in the background for a newer release. It takes a release as soon as it is out and serves the BaseRT engine you have installed; `superfluid self auto-update wait 3` makes it wait until a release has been out three days instead. The next `serve`, `launch`, `node`, `top` or `runtime` command you start in a terminal then updates first: superfluid downloads the release, checks it against its sha256 and tries it before switching to it. It then updates every runtime you installed that is not pinned, and repairs one whose build did not change so its worker matches the new superfluid. A runtime that a running server uses, including the BaseRT library inside a server's worker, is left alone with a message saying so. Your command then runs on the new version, and the notice shows the release-notes link and how to go back or turn updates off. If an update cannot finish (offline, another update running, a failed check, Ctrl-C), superfluid says so, carries on with the version you have, and tries again the next day.
- **Installs from a package manager.** A Homebrew, global npm, cargo, pipx or uv install updates in the background through its own manager once no superfluid runs from that copy, and logs to `auto-update.log` in superfluid's log directory. pip, a project-local npm install and Windows get a notice with the command to run instead. A copy that BaseRT's `basert` installed is updated by `basert`.
- **Turning updates off or going back.** `superfluid self auto-update off` turns automatic updates off (`on` turns them back on; without an argument it says which is in effect and why). Superfluid Desktop uses the same setting. `--no-update` on any command skips updating for that run, and `SUPERFLUID_NO_UPDATE=1` turns off the update and the check for a shell or a service. `superfluid self use <version>` goes back to an earlier release, and an automatic update leaves it there until a newer one is out. Updates never run without a terminal (services, apps, pipes), when `CI` is set, or for informational commands such as `--json`, `runtimes`, `models` and `self`.
- 0.2.1 and earlier do not have the updater, so update to 0.2.2 the usual way once. See [updating](https://github.com/basecompute/superfluid/blob/v0.2.2/docs/serving/updating.md).

## Changed

- **`superfluid runtime install`, `repair` and `remove` no longer replace a runtime a server is using.** They refuse while a running server uses that install.
- **llama.cpp b12776** is the build `superfluid runtime install llamacpp` installs on macOS, Linux and Windows, where 0.2.1 installed b12651 on macOS and Linux and b12631 on Windows. b12722 and b12676 are tested builds too, on all three, and the builds 0.2.1 listed stay.
- **MLX 0.32.5 with mlx-lm 0.32.2** is what `superfluid runtime install mlx` installs, where it was MLX 0.32.4. The Python it uses is unchanged.

The engine ABI is unchanged: superfluid 0.2.2 serves BaseRT 0.5.5, released alongside, and the 0.5 and 0.4 releases as 0.2.1 does. `superfluid runtime install basert` installs it.

See [installation](https://github.com/basecompute/superfluid/blob/v0.2.2/docs/getting_started/installation.md) for every way to install superfluid, and [updating](https://github.com/basecompute/superfluid/blob/v0.2.2/docs/serving/updating.md) for how each is updated.
