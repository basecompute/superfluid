# superfluid 0.2.1

**A fleet node now drains when asked, and `superfluid launch` no longer
starts a server for another machine's address.** `superfluid node join`
finishes the requests it is running before it exits, as `superfluid serve`
does, so a node can leave a fleet without cutting anyone off. `superfluid
launch` says why a server on another machine did not answer, where it used
to start one here that could only fail, and on Windows it runs the agents
npm installs. llama.cpp b12651 is the newest build superfluid installs on
macOS and Linux.

## New

- **Drain a fleet node.** `superfluid node join` now drains on the same
  asks a server does: `kill -USR1 <pid>` on macOS and Linux, `superfluid
  stop --drain --pid <pid>` on any system, and Ctrl+Break in its console
  on Windows. A draining node takes no new work, lets each request it is
  running finish and exits with code 0; the head sends new requests and
  sessions to its other nodes, as it does when a node leaves. Requests
  still running after `--drain-timeout`, new on `superfluid node join` and
  60 seconds by default as on `serve`, are cut. With `--log-format json`
  the node reports `node.drain.start` and `node.drain.done`. Nothing
  changes on the head or between head and node. On a Mac, a node serving
  gemma-3-1b-it drained during a 1500-token stream: the stream finished
  whole, and a request sent during the drain was not sent to it. See
  [failure handling](https://github.com/basecompute/superfluid/blob/v0.2.1/docs/serving/distributed_serving.md#failure-handling).

## Changed

- **A shorter install line on Windows.** In PowerShell,

  ```
  irm https://basecompute.co/sf/install.ps1 | iex
  ```

  installs superfluid, and it is the line the README, the docs,
  superfluid's own messages and the macOS and Linux installer (run from
  Git Bash, MSYS2 or Cygwin) now give. The address it replaces, on
  GitHub's releases, still works.
- **llama.cpp b12651** is the build `superfluid runtime install llamacpp`
  installs on macOS and Linux, and b12631 on Windows, where b12503 and
  b12470 stay. b12631, b12535, b12503, b12470, b12435, b12408, b12359,
  b12317, b12283, b12244, b12219, b12207, b12125, b12102, b12068, b11981,
  b11951, b11925, b11890, b11889, b11642 and b11284 stay on macOS and
  Linux. b12651 did not pass its tests on Windows, so Windows installs it
  only with `--untested`.

## Fixed

- **`superfluid launch` no longer starts a server for another machine's
  address.** With `--http` naming another machine, `launch` started
  `superfluid serve` on this one whenever nothing answered there, and that
  server failed with "the server exited (exit status: 1)", which hid the
  reason. At another machine's address `launch` now starts nothing and
  stops with `can't reach the server at <addr>: <why>`, where the reason
  is what the system said: a connection that timed out or was refused, an
  HTTP error, or an answer that was not a model list. At an address of
  this machine (`127.0.0.1`, `localhost` or one of its own addresses) it
  still starts a server when none answers, and `--print` still shows the
  plan. On macOS, a terminal app that is not allowed on the local network
  cannot reach other machines there, though Apple's own `curl` still can;
  when that is the reason, `launch` says so and where to allow it: System
  Settings › Privacy & Security › Local Network.
- **Agents installed with npm run on Windows.** `superfluid launch` listed
  pi, codex, cline and openclaw as installed when npm had installed them,
  but launching one failed with `could not run pi: program not found`.
  They run now. The install commands `launch` shows on Windows are
  PowerShell's: `irm https://claude.ai/install.ps1 | iex` for Claude Code,
  `irm https://hermes-agent.nousresearch.com/install.ps1 | iex` for Hermes
  Agent and `npm install -g opencode-ai` for OpenCode, where every system
  was shown a `curl … | bash` line.

The engine ABI is unchanged: superfluid 0.2.1 serves BaseRT 0.5.4,
released alongside, and the 0.5 and 0.4 releases as 0.2.0 does.
`superfluid runtime install basert` installs it.

See [installation](https://github.com/basecompute/superfluid/blob/v0.2.1/docs/getting_started/installation.md)
for every way to install superfluid, and
[updating](https://github.com/basecompute/superfluid/blob/v0.2.1/docs/serving/updating.md)
for how each is updated.
