Supported models

Superfluid serves whatever its runtimes read: GGUF files through llama.cpp, MLX model directories through MLX, and .base bundles through the baseRT engine. A model is given as a local path or as a Hugging Face-style id that the runtime pulls.

Formats and runtimes

"Per bundle" means the bundle's capability record decides once it is loaded. Anything a model cannot do is refused per request with a 400 naming the reason. See Runtimes.

Paths and ids

superfluid serve ./Qwen3-4B-Q4_K_M.gguf                  # a path; format picks the runtime
superfluid serve ~/models/Qwen3-4B-4bit                   # an MLX directory
superfluid serve unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_M           # an id, pulled by llama.cpp
superfluid serve mlx-community/Qwen3-4B-4bit              # an id, pulled by MLX
superfluid serve basecompute/Qwen3-1.7B                   # an id, pulled by basert

A token is an id when nothing exists on disk by that name, it does not start with ., / or ~, it does not end in .base or .gguf, and the part before an optional :tag contains a /. Anything else is a path, so a missing file is reported as missing rather than looked up on a hub.

formserved under
a file pathits stem (./model.gguf → model)
a directorythe directory name
a .base bundle in the hub cache (with hub.json beside it)the id hub.json records
org/model[:tag]org/model (the tag is dropped)

Runtime inference for ids: a repo name containing gguf (any case) goes to llamacpp; mlx-community/... or a repo name containing mlx goes to mlx; anything else to basert. --runtime overrides it.

Pulling models by id

Pulling happens during superfluid serve; there is no separate pull command.

runtimetool:tag means--pull-<name> optionscache
llamacppllama download -hfthe quant (Q4_K_M), or a size (medium) of a release in sizes--pull-file <name>, --pull-no-mmprojHugging Face cache
mlxhuggingface_hub.snapshot_downloada revision--pull-revision <rev>Hugging Face cache (no *.py files are fetched)
basertbasert pull, then basert list --json for the patha variant, or a size--pull-target <scheme>, --pull-profile <json>, --pull-revision <rev>, --pull-file <name.base> (one of several in a repo; served from the install basert list records it in), --pull-forcethe baseRT models cache (BASERT_MODELS_DIR)
  • --offline only looks in the cache and fetches nothing.
  • A pull shows its progress on stderr: the percentage, the bytes fetched of the total, the rate and the time left, redrawn on a terminal and printed every ten seconds where there is none, then one line with the size, time and rate it took. Superfluid reads this from what the runtime's tool writes into its cache, so it is the same for every runtime; the total is the file's size from the Hub's listing (the GGUF llama download picks, with its shards and projector; the files snapshot_download takes; a catalog model's size from basert list --remote), and a pull whose total could not be looked up (or under HF_HUB_OFFLINE, which keeps the lookup off the Hub) shows the bytes, rate and time elapsed. A pull that resumes a partial starts the bar where it left off and reports the rest as what it fetched. Once every byte is here and the tool is still verifying, converting or copying, the bar says so.
  • A release in sizes is a repository whose model files are named by size, the BaseQuant repositories' -XS, -Small, -Medium, -Large and -XL, and none by quant. With nothing naming a file, both runtimes pull its Medium: superfluid serve basecompute/Qwen3.8-27B-BaseQuant-V1 --runtime basert and --runtime llamacpp serve Qwen3.8-27B-BaseQuant-V1-Medium.base and .gguf. A size tag takes another (basecompute/Qwen3.8-27B-BaseQuant-V1:small), --pull-file <name> a file; a size the release does not come in names the ones it does, and a release of one file gives that file. The llamacpp runtime reads the repository's listing from the Hub for this (llama.cpp's own pick, with no file named, is some file of the repository, not the Medium, and it refuses a size tag as not a quantization); a listing that fails leaves a plain pull to llama.cpp with a warning, and --offline lists nothing, so there a size spells its file as the releases name them (<repo>-Small.gguf) and no tag is left to llama.cpp's cache. The basert runtime's basert pull reads these releases by the same rule from basert 0.4.5; a size with basert 0.4.2–0.4.4 is passed as --file <repo>-<Size>.base, and each file installs under a file-… variant that records it, which a size tag is served from.
  • A baseRT variant is named as basert list names it (default-q8, file-…). One that is installed is served without a pull (unless --pull-force); one that is not is pulled as named with basert 0.4.2 or later (basert pull org/model:<variant>, without --pull-file, --pull-profile or --pull-target, which would name it twice), and with an older basert by the id alone, which fetches the quant its options pick.
  • An undeclared --pull-* option, or --pull-* with no model given by id, is refused before anything is fetched.
  • A gated or private model needs HF_TOKEN.
  • One pull of an id runs at a time across daemons.

Published sampling defaults

When a request names no sampling parameter, the model author's published defaults apply (after any operator --temperature etc.):

runtimesource
llamacppGGUF general.sampling.* metadata (older conversions carry none)
mlxgeneration_config.json
basertthe bundle header

They appear in superfluid runtimes <model>, /v1/models and /props. See Sampling.

Context and batch sizing

flagdefaultmeaning
--max-context <N>autoper-lane window, sized for the device: basert before loading, llamacpp on Metal or a dedicated CUDA GPU, mlx on Metal; elsewhere 8192
--max-batch <N>8concurrent lanes
--kv-bits <N>0 (auto)KV type on basert only

On llama.cpp and MLX the KV pool is --max-batch × --max-context cells, capped by the memory the weights leave free; the cap is printed at load. A prompt that does not fit the window is refused with context_length_exceeded.

Checking a model

superfluid runtimes ./Qwen3-4B-Q4_K_M.gguf

Prints which runtime reads it, the model's architecture and sampling defaults, and what that runtime serves and refuses. Exits 1 when no installed runtime serves it.
